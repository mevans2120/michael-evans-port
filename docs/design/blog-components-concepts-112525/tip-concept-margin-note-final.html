Research → Plan → Build ↔ Test

If someone were to ask me "What's your secret?" I would point to quite a few tools and techniques that I use. But for me, the most important process to follow when designing and building with AI is to be diligent about following this workflow at nearly every step.

Research

Tip

There are no dumb questions — ask the agent to clarify anything you don't understand.

First, I ask the agent to research whatever it is we're trying to accomplish, provide options where applicable, and outline pros and cons. This can happen at the beginning of a project when trying to determine the feasibility of a particular feature or idea, or when trying to debug a complex or tough-to-solve issue.

Examples include researching whether creating a Claude Code skill for memory and context management is a good idea, or investigating why preview mode in the Sanity CMS is still revalidating instead of using webhooks.

Plan

Tip

Always save the research and planning docs as .md files.

After I review the research and ask any questions I have, I ask the agent to take the research and whatever approach we agreed upon (if applicable) and create a phased project plan with success metrics. If it's a smaller bug and the fix is only a few lines of code, I'll skip the planning phase.

Once I've reviewed the research and asked for revisions if needed, I ask the agent to create a phased project plan based on the findings, with measurable success metrics. After reviewing this plan and asking questions about anything I don't understand, I ask the agent to start on phase 1.

Build ↔ Test

Pro tip

Fix failures right then and there — don't let them pile up.

Now that we've started building, I compare what we're building against the success metrics to determine when is the best time to test. Should it be after phase 1, phase 2, etc.? If I don't know the answer, I'll ask the agent.

The important part is that you and the agent get a chance to test and measure success. If you discover failures and improvement areas during the build process, I like to fix them right then and there.
