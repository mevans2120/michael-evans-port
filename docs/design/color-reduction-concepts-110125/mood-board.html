Color Concepts: Reduced Purple Usage

Two approaches to minimize purple while keeping it as a strategic accent

Strategic Goal

Current state: Purple is used heavily throughout (buttons, hovers, borders, accents)
Desired state: Purple reserved for navigation border and key accents only
Challenge: What replaces purple for secondary elements (button states, hover effects, strokes)?

Concept 1: Minimal Gray

Ultra-minimal aesthetic using only grays for all UI elements. Purple appears sparingly for navigation border and critical accents.

Design Rationale

This concept embraces extreme minimalism. By using only grays for UI, purple becomes a powerful signal when it appears. Similar to how Stripe or Linear use minimal color palettes to create focus.

Strengths

  • Purple accent feels intentional, not default
  • Clean, professional aesthetic
  • Easy to implement (fewer colors)
  • Works beautifully in dark mode

Tradeoffs

  • Less colorful/vibrant overall
  • May feel too minimal for creative portfolio
  • Harder to create visual hierarchy without color
Technical Implementation
CSS variable changes needed
/* globals.css - Light Mode */
:root {
  /* Replace purple with grays */
  --color-button-primary: 0 0% 20%;
  --color-border: 0 0% 30%;

  /* Keep purple for accents only */
  --color-accent: 276 70% 45%;
  --navigation-border: 276 70% 45%;
}

/* Secondary buttons */
--secondary: 0 0% 25%;
--muted: 0 0% 30%;

/* Hover states */
.hover\:bg-gray-750 {
  background: hsl(0 0% 25%);
}
Migration Path
  1. Update --color-button-primary from purple to gray
  2. Update --secondary and --muted to neutral grays
  3. Keep --color-accent purple (navigation only)
  4. Replace purple hover states with gray variants
  5. Test dark mode equivalents

Design Rationale

Blue-gray provides a cool, technical aesthetic while reducing purple dominance. The blue tint complements purple (analogous on color wheel: purple 276° → blue 210°) and feels modern, like VSCode or GitHub's dark themes.

Strengths

  • More colorful than pure gray
  • Blue-gray feels technical/professional
  • Colors complement each other (analogous)
  • Suits AI/ML portfolio theme

Tradeoffs

  • Adds another color to manage
  • Blue-gray may feel "corporate" to some
  • Less striking contrast than Concept 1
Technical Implementation
CSS variable changes needed
/* globals.css - Light Mode */
:root {
  /* Replace purple with blue-gray */
  --color-button-primary: 210 20% 30%;
  --color-border: 210 15% 25%;

  /* Keep purple for accents only */
  --color-accent: 276 70% 45%;
  --navigation-border: 276 70% 45%;
}

/* Secondary elements */
--secondary: 210 25% 35%;
--muted: 210 15% 30%;

/* Card hover states */
.card-interactive:hover {
  background: hsl(210 10% 12%);
  border-color: hsl(210 20% 35%);
}
Migration Path
  1. Update --color-button-primary from purple to blue-gray (210° hue)
  2. Update --secondary and --muted to blue-gray variants
  3. Keep --color-accent purple (navigation only)
  4. Replace purple hover states with blue-gray
  5. Test dark mode with lighter blue-gray variants

Recommendation

Concept 1: Minimal Gray

Best for: Ultra-minimal aesthetic, letting content shine, maximum purple reduction

Choose if: You want the most dramatic change, prefer minimal design languages (Linear, Stripe), or want purple to feel truly special when it appears.
Concept 2: Blue-Gray Complement

Best for: Technical aesthetic, more color than Concept 1, AI/ML portfolio theme

Choose if: You want some color beyond pure gray, prefer cooler tones that suit technical portfolios, or like the VSCode/GitHub aesthetic.
💡 My Recommendation: Concept 2 (Blue-Gray)

For an AI/ML portfolio, blue-gray feels more appropriate than pure gray. It maintains a technical aesthetic while providing more visual interest than Concept 1. The cool tones complement your purple accent and align with industry expectations (think GitHub, VSCode, Vercel). Purple remains strategic for navigation and key CTAs, creating clear visual hierarchy.
